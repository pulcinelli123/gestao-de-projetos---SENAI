## 1. Objetivo da aula

Entender o que é um processo, diferenciar **grupos de processos** de **áreas de conhecimento** e aprofundar o **Gerenciamento do Escopo**: requisitos, técnicas de coleta e Estrutura Analítica do Projeto (EAP).

## 2. Resumo do conteúdo

### 2.1 O que é um processo?
Conjunto de atividades realizadas para transformar **entradas** em **resultados**. Exemplo: solicitação do cliente → análise e desenvolvimento → funcionalidade entregue. Em projetos, os processos ajudam a organizar, executar e controlar o trabalho. Pergunta provocativa da aula: *o que acontece com um projeto sem processos bem definidos?*

### 2.2 Os cinco grupos de processos

| Grupo | Finalidade |
|---|---|
| **Iniciação** | Autorizar e definir o projeto |
| **Planejamento** | Definir como o projeto será realizado |
| **Execução** | Realizar o trabalho planejado |
| **Monitoramento e controle** | Acompanhar resultados e corrigir desvios |
| **Encerramento** | Finalizar e formalizar o projeto |

### 2.3 Processos × Áreas de conhecimento
- **Grupos de processos** mostram **quando** e com qual finalidade o gerenciamento acontece.
- **Áreas de conhecimento** mostram **o que** precisa ser gerenciado.

Exemplo da aula, um **aplicativo de delivery**: iniciação (objetivo, escopo, stakeholders) → planejamento (prazo, custos, riscos) → execução (desenvolvimento) → monitoramento (prazo, custos, qualidade) → encerramento (entrega e lições aprendidas).

### 2.4 Gerenciamento do Escopo (área 5)

| Processo | Descrição |
|---|---|
| **5.1 Planejar o gerenciamento do escopo** | Plano que documenta como o escopo será definido, validado e controlado |
| **5.2 Coletar os requisitos** | Determinar, documentar e gerenciar necessidades e requisitos das partes interessadas |
| **5.3 Definir o escopo** | Descrição detalhada do projeto e do produto |
| **5.4 Criar a EAP** | Subdividir entregas e trabalho em componentes menores e gerenciáveis |
| **5.5 Validar o escopo** | Formalizar a aceitação das entregas concluídas |
| **5.6 Controlar o escopo** | Monitorar o escopo e gerenciar mudanças na linha de base |

### 2.5 Requisitos e sua classificação
Requisito é parte ou condição necessária para que o projeto possa ser realizado e tenha sucesso.

1. **Necessidades de negócios:** necessidades de mais alto nível da organização (problemas ou oportunidades que motivaram o projeto).
2. **Requisitos das partes interessadas:** necessidades de um stakeholder ou grupo.
3. **Requisitos de solução:** atributos, funções e características do produto/serviço/resultado.
4. **Requisitos de transição:** capacidades temporárias (conversão de dados, treinamento) para ir do estado atual ao futuro.
5. **Requisitos de projeto:** ações, processos ou condições que o projeto deve cumprir.
6. **Requisitos de qualidade:** condições ou critérios para validar a conclusão de uma entrega.

### 2.6 Técnicas para coletar requisitos
Entrevistas; grupos de discussão; brainstorming; mapas mentais; questionários e pesquisas; observações; benchmarking.

### 2.7 Estrutura Analítica do Projeto (EAP)
Decomposição hierárquica do escopo total do trabalho a ser executado pela equipe para alcançar os objetivos e criar as entregas exigidas. Cada nível descendente representa uma definição cada vez mais detalhada do trabalho.

## 3. Atividade proposta

Elaborar a **EAP do Projeto FieldOps**, com um diagrama que mostre as principais informações da estrutura do projeto e seus requisitos, entregue no repositório do GitHub. O repositório de origem traz os modelos `Modelo - 5.1 Estrutura Analitica do Projeto.md` e `Modelo - 5.2 Estrutura Analitica do Projeto.png`.

## 4. Conclusões e aprendizados

- Processos transformam entradas em resultados; os cinco grupos dizem *quando* gerenciar e as dez áreas dizem *o quê*.
- O escopo se constrói de requisitos bem coletados até a EAP, e só se fecha com a validação formal das entregas.
- A EAP é a base para estimar prazo, custo e responsabilidades nas aulas seguintes.
